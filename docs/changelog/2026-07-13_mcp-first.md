# 2026-07-13 — MCP-first: o MCP do Konecty executa, as skills guiam

## Resumo

Refatoração arquitetural completa (feature `mcp-first`, ADR-0006): as skills deixam de
embarcar scripts HTTP e passam a ser guias procedurais sobre os servidores MCP nativos
do Konecty (`/mcp` e `/admin-mcp`). Nova promessa de setup: **instalar → informar a URL
da empresa → login no navegador → conversar com o CRM**.

## Mudanças

### Skills

- **konecty-data** reescrita como guia fino do MCP de usuário: `SKILL.md` roteador +
  references por fluxo (field-discovery, find, create-update, delete, files, auth,
  errors). `scripts/` removido.
- **konecty-meta** reescrita como guia fino do MCP admin (12 tools `meta_*`), com
  guardrails de full-replace (read-modify-write), hook validate→upsert e a lacuna de
  remoção de módulo documentada (sem workaround REST). `scripts/` removido.
- **konecty-setup** (nova): setup e reconfiguração conversacional dos servidores MCP,
  com matriz de troubleshooting.
- Invariante de shared-files dissolvido: `shared-files.txt`, guard de pre-commit,
  GitHub Action `check-shared-files` e `make shared-check` removidos.

### Instalador

- `install` registra os servidores MCP (`konecty` user-scope; `konecty-admin` com
  header Bearer interino) via `claude mcp add`, valida a URL pelo
  `/.well-known/oauth-protected-resource`, copia as 4 skills; idempotente (replace,
  nunca duplica). Sem o CLI `claude`, imprime os comandos exatos.
- `doctor` valida well-known + match de audiência (`PLATFORM_MCP_RESOURCE_URL`),
  registro MCP e validade do token admin.
- `credentials.py` reduzido ao papel de token admin interino (`~/.konecty/.env`).

### Upstream (Konecty)

- Escopo OAuth `admin` para clientes confiáveis no consentimento —
  [konecty/Konecty#453](https://github.com/konecty/Konecty/pull/453) (ADR-0011 lá):
  predicado `trustedFirstParty ∧ admin ∈ allowedScopes ∧ user.admin`, opt-in explícito
  no consent, receita de provisionamento via `OAUTH_CLIENTS_JSON`.

### Harness E2E (substituído)

- Stack Docker constrói o Konecty **do código-fonte local** (worktree
  `e2e/.konecty-src`), com env de audiência consistente, 2 clientes OAuth seedados
  (normal + confiável admin) e bootstrap das flags MCP de namespace via mongosh.
- Cliente MCP JSON-RPC stdlib (`tests/e2e/mcp_client.py`) + 4 suítes (39 casos):
  smoke/transporte, user MCP (todos os fluxos do konecty-data, incl. OTP com código
  lido do `data.Message` e caso read-only `insufficient_scope`), admin MCP (todos os
  fluxos do konecty-meta + guard errors 503/403) e OAuth (DCR→PKCE→consent→token→MCP,
  escopo admin de cliente confiável, invalid_scope para não confiável).
- Harness antigo (pseudo-agente de scripts, MockKonecty, suítes mock/live/security/
  inference, gate de cobertura ≥90%) removido; `make e2e` = ciclo limpo pass/fail;
  `make test` vira alias de `e2e-run`.

### Documentação

- README (pt-BR + EN) reescritos para a nova história; AGENTS.md atualizado
  (comandos, modelo de auth, mapa de skills); ADR-0006 registrado.

## Impacto

- **Breaking:** instâncias Konecty sem MCP não são suportadas — fixe a última tag
  script-based. Fluxos de credencial antigos (`~/.konecty/.env` como fundação geral)
  substituídos pelo OAuth nativo + token admin interino.
