# Changelog: E2E test harness (dockerized stack + pseudo-agent + 93% coverage)

## Date

2026-06-17

## Summary

Added a self-contained, reproducible end-to-end test harness that boots a disposable Konecty stack and drives every subcommand of both skills via a deterministic pseudo-agent, reaching **93% line coverage** with a `--fail-under=90` gate.

## What changed

- **`e2e/docker-compose.yml`** — disposable stack: MongoDB (replica set `rs0`) + `mongodb-init` + RabbitMQ + `konecty/konecty:3.8.10` on alternate ports (Konecty `:3200`, Mongo `:27117`) so it coexists with a dev Konecty on `:3000`. `docker compose down -v` gives a clean DB and fresh admin each round. Boot requires `COOKIES_SECRET` + `NODE_ENV=production` (so 3.8.10 loads its 21 shipped seed metas).
- **`e2e/scripts/konecty_admin_token.py`** — reads the admin password from container logs, logs in with the raw-password scheme + `Sec-Fetch-Site: none` header (the sha256 scheme is gone in 3.8.10), and prints/writes the token.
- **`e2e/scripts/wait_for_konecty.py`** — polls `/liveness` until the stack is healthy.
- **`tests/e2e/agent.py`** — pseudo-agent that calls each skill script's `main(argv)` in-process (so `coverage.py` tracks argparse + dispatch + handlers) and runs a handful of subprocess smoke calls.
- **`tests/e2e/intents.py`** — deterministic intent router: maps PT/EN phrases → skill commands without an LLM.
- **`tests/e2e/mock_konecty.py`** — extended in-memory `MockKonecty` implementing the full data + query + file + auth + meta contract (the meta side implements the `/api/admin/meta/*` surface from Konecty PR [#299](https://github.com/konecty/Konecty/pull/299)).
- **`tests/e2e/test_live_data.py`** (`live` marker) — live suite driving the konecty-data subset the public 3.8.10 image supports: `auth login-options`, `modules`, `find`, `create`, `update` (explicit ids). Skipped when the stack is down.
- **`tests/e2e/test_data_mock.py`** + **`tests/e2e/test_meta_mock.py`** (`mock` marker) — mock-coverage suites driving every subcommand of both skills (including the drifted query paths and all 11 meta subcommands) so the ≥90% gate is met without a stack.
- **`tests/e2e/test_security.py`** — 8-criterion security suite: credential fast-fail, bad-token 401 (no traceback), delete/upload `--confirm` guards, OTP local validation, invalid hook/webhook rejection, token-not-leaked, injection payloads transported as data.
- **`tests/e2e/test_inference.py`** — intent-router assertions: PT/EN phrases → expected subcommands.
- **`pytest.ini`** + **`.coveragerc`** — configuration for `--fail-under=90`, term-missing + HTML (`tests/coverage_html/`) + XML reports, source paths `skills/konecty-data/scripts` and `skills/konecty-meta/scripts`.
- **`Makefile`** — 10 new `e2e-*` targets (see README). Suite runs via `uv run --with pytest --with coverage` (avoids PEP-668 externally-managed-python conflicts).

## Architecture notes

**Hybrid test architecture (D9):** konecty-data is tested live where the public image agrees and against `MockKonecty` for the drifted paths (`/rest/query/json` requires a `relations` array on the public image). konecty-meta is fully mocked — the `/api/admin/meta/*` admin API is correct in the skill but only exists in Konecty PR #299 (not yet published). Live swap for both deferred paths is intentionally structured as a transport-layer change only (D8).

Total: ~473 tests, 93% coverage.
